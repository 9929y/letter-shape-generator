# Letter Shaper Studio

粒子造字机。单文件 HTML 工具:输入文字,数千个粒子填充字形轮廓,持续颤动呼吸,可在多段文字之间炸开重组,也可以做成 hover 才聚合的交互效果,或者打开摄像头用手去推、去抓。调好之后能导出成 Vanilla JS / React / Vue 组件,或者 PNG / WebM / GIF。

**零依赖,离线可用。** 双击 `index.html` 就能跑,不需要构建、不需要服务器、不联网。界面用的两款开源字体(DM Sans / JetBrains Mono)以 latin 子集 base64 内嵌在文件里,所以断网也是同一个样子 —— 这也是单文件从 ~127KB 涨到 ~240KB 的原因。

## 用法

打开 `index.html`。左边是画布,右边是一张和画布等高的浮窗面板 —— 两张卡片浮在页面上,不是贴着窗口边的两块板。

面板顶部固定的部分:

- **Text** — 支持中文整句。**Loop 模式下一行就是一个短语**,会依次循环 —— 文字只在这一个地方定义,没有第二个输入框。单字符时用 `↑` `↓` 循环 A–Z 0–9。字数越多字号自动越小,始终居中在画布内
- **Loop / Hover / Gesture** — 三种模式,见下,右边是 Play

固定区下面,先是当前模式自己的东西(只有 Gesture 模式有),然后一条 **Settings** 分隔,底下是设计本身:Shape · Particle · Scale · Colour · Motion。

两个画廊曾经是两排长得几乎一样的胶囊,谁也看不出自己在改哪一轴,所以现在**各自画自己那一轴**:

- **Shape(形状)** — 五个预设:Confetti / Brickwork / Numerals / Mist / Pebbles。每张卡片用**单色油墨**把自己那套粒子真的画一遍(同样的形状、同样的大小分布、同样的旋转),所以你看到的就是你会得到的形状。**它不再动你的颜色** —— 选形状就只是选形状
- **Particle** — Circle / Square / ASCII,每颗粒子本身是什么记号
- **Scale** — 一根滑杆代替了原来的 Density + Grain:往右粒子变大、数量自动变少,往左变小、数量变多(读数是 `15 px · 2920`)。粒子数不用你自己算
- **Colour(颜色)** — 七套配色,**每套自带配好的背景色**:Classic / Morandi / Ink / Chalk / Ember / Sea / Moss。卡片上只有颜色:自己的底色,加一条按权重分宽度的色条
  - 画廊正下方就是**这套配色的九个色点**(点开可改颜色和出现频率、可增删)和**背景色** —— 不再藏在别的抽屉里
  - 手动改过任何一个颜色,选中态会掉成 **Custom**;点画廊里的 **+ Save palette** 就把当前这套(颜色 + 背景)存成你自己的配色,和内置的排在一起,**存在 localStorage 里,刷新还在**,hover 卡片右上角的 × 可以删

选中态是**中性的深色描边加一个对勾**,不是红圈 —— 红色在一堆颜色上面读起来像报错。

最后只有一个抽屉,默认收起:

- **Motion** — **Liveliness**(颤动与呼吸)· **Tempo**(循环节奏,仅 Loop)· **Spread**(散开范围),外加 **Shuffle**(换一版构图:同样的字、同样的颜色,粒子换一种排布)。一根滑杆背后写的是原来的两三个参数,而且是**按当前比例缩放**而不是写死一对值 —— 所以 Brickwork 那种粗颗粒被你推一下之后还是粗的
**Export 在面板最底下**,不在顶栏里 —— 它是流程的终点,就放在流程的终点。

**被删掉的**:min/max size、edge feather、opacity、tremble 三项、三段时长、rotation、stack density、Density、Grain —— 这些要么已经被上面的合并滑杆覆盖(同一个参数有两个入口比只有一个更糟),要么只由预设设定、没人会手动去调。参数本身都还在:预设照常写它们,**导出的 cfg 仍然是完整可改的参数集**,只是界面上不再摆出来。

折叠状态会记住。

### 三种模式

- **Loop** — 粒子按 Text 里的短语循环:停留 → 炸开 → 重组成下一段文字。**Text 一行一个短语**;只写一行就是同一段文字反复炸开重组
- **Hover** — 粒子散开漂浮在整个画布上,鼠标悬停时飞入聚合成文字,移开再散开。触屏是按住 / 松开
- **Gesture** — 用摄像头跟手互动。字保持成形,手是一个力场:**摊开手掌**把附近的粒子推散开,**握拳**把它们吸过来抓在手里、跟着手走,**再摊开**就炸出去、各自弹回字形里

### Gesture 模式

切到 Gesture,面板上就多出一个 **Gesture** 区块 —— 不是抽屉,是展开的,因为在这个模式下它就是这个模式本身。区块从上到下:**Turn on camera** 按钮,**紧挨在按钮下面的摄像头预览**,一行状态说明,再是**三条常驻的手势说明**(摊掌推散 / 握拳抓取 / 手离开画面回落),然后是 Effect 和 Strength。

画布上什么浮层都没有了。以前是一颗 CTA 加一张三格图示加一个悬浮预览,三层东西盖在作品上说同一件事,而且那张图示识别到手就消失 —— 整个模式唯一的说明,恰恰是你回头查不到的那个。

画面只在这个标签页里跑:每帧被画进一张 160 × 120 的临时 canvas 做识别,用完即弃,不上传、不留存。预览框底部标签显示 `Open palm` / `Fist` / 没找到手;**认错了东西就直接点预览里正确的那块**。

**三种效果**,一个选择器加一根 Strength:

- **Scatter**(默认)— 摊掌把字推散,而且**推开就散在那儿**,手在画面里它就保持散开;手一离开,粒子在 reform 时长内各自落回字形。这是靠一个 latch 做的:被推开的粒子会暂时切断回字形的弹簧,不然弹簧会瞬间把它拉回去,看起来只是荡了一下
- **Reveal** — 反过来,字平时是散的,手扫过的地方才聚成字形,手走了慢慢散回去
- **Magnet** — 纯力场,不带 latch:握拳吸附并拖着走,摊掌推开

识别是纯手写的,关键在于怎么把手和脸分开:肤色阈值(RGB 规则 + YCbCr 窗口)、会衰减的运动累积量、3 × 3 中值滤波、连通域标记,然后是**空洞检测**——眼睛、鼻孔、嘴不是肤色,会在脸这块色斑中间捅出封闭的洞;手没有(指缝是通到外面的,不算洞)。实测:脸的封闭空洞占 4.4% 面积,手是 0.0%。评分还改成按 √面积,免得脸靠"大"直接压过手;锁定之后会粘住,但如果锁住的东西长时间不动,会松开让真正在动的手接管。

摄像头需要安全上下文:`https` 或 `localhost` 一定可以;Chrome / Edge 直接双击本地 `index.html`(`file://`)也行,Safari 不行。

## 导出

Export 按钮,两类:

**Code** — 把当前面板的所有参数(含生效的色板和模式)烘焙进自包含代码:

- `Vanilla JS` — 一个 `<canvas>` 加一段 IIFE,直接贴进任何页面
- `React` — 函数组件,`useRef` + `useEffect`,cleanup 里 `cancelAnimationFrame`;`text` / `colors` / `mode` 可用 props 覆盖
- `Vue` — Vue 3 SFC,`<script setup>`,`onMounted` / `onUnmounted`

导出的代码内联的是页面里同一个 `particleTextEngine` 函数(通过 `Function.prototype.toString()` 序列化),所以线上跑的和你在工具里看到的是同一套渲染逻辑。Gesture 模式还会一并内联 `handTracker`,并给 canvas 接一个「首次点击开摄像头」的手势(浏览器不点不给流)。

**Media**

- `PNG` — 当前帧,1200 × 1200 原尺寸
- `WebM` — 录一个完整循环(Hover 模式录一段完整手势演示;Gesture 模式录 8 秒实时表演,你在镜头前做什么就录到什么)。`captureStream(0)` 加逐帧 `requestFrame()`,一画一帧;编码格式 vp9 → vp8 → 裸 webm 逐级探测,Safari 不支持时按钮禁用
- `GIF` — 480 × 480 / 14fps,内联手写的 GIF89a 编码器(无外部库)。首帧按 RGB555 桶采样取 256 色全局调色板,后续帧走 32768 项最近邻查表;标准 LZW 带位宽增长与字典重置

## 实现要点

- **确定性**:所有结构性随机(粒子属性、mask 采样、散开目标)都来自一个 LCG seeded RNG。`Math.random()` 全文件只出现两处:Shuffle 按钮和「加一个随机颜色」按钮
  - seed 本身不在界面上 —— 它是工程师词汇,没人会手输 `88172645` 回去。可复现性没有丢:seed 存在 state 里、进撤销历史(所以 `⌘Z` 能把上一版构图找回来)、并且烘焙进每一份导出代码 —— 真要复现某张图,是从导出的 cfg 里拿,不是从界面上抄
- **实时性**:非结构性参数(颤动 / 呼吸 / 各段时长 / 背景 / 形状)按引用逐帧读取,拖动滑杆即时生效;结构性参数(Scale / 色板 / seed)在松手时重建粒子池
- **Scale 的曲线**:`count = 36000 / size`,size 从 6px 到 26px,数量从 6000 到约 1385 —— 粒子减半就多一倍,两端的字看上去一样实。上下限是挑过的:滑杆的头三分之一如果卡在数量上限上什么都不变,那还不如把滑杆做短一点
- **配色画廊**:内置七套写死在 `THEMES`,自存的进 `USER_THEMES`(`localStorage` 的 `lsg.palettes.v1`),`themeById` 两边一起查。存的是颜色**和背景**——只存颜色的话,配色和底色迟早又会各走各的
- **形状卡片**:每张卡片是一张 110 × 70 的 canvas,拿一个字母 `A` 的 alpha mask 当采样区,按该预设的 shape / 尺寸分布 / 旋转真的画一遍,油墨取当前页面的 `--text`(所以切 light / dark 会重画)。随机数是定种子的,卡片不会每次刷新都变一个样
- **性能**:圆点与砖块形态在 2920 粒子下稳定 60fps。零 per-particle `save/restore`;ASCII 形态用 glyph × color 预渲染 sprite 加单次 `setTransform` + `drawImage`,替代每帧几千次 font 赋值和 `fillText`;圆点直接 `arc`(旋转对圆是视觉空操作);砖块纯轴对齐 `fillRect`;`globalAlpha` 只在变化时写入
  - **已知问题**:ASCII 形态在 3400 粒子下只有约 13fps(无 GPU 的无头 Chromium 实测)。这是既有问题,不是本轮改动引入的 —— 同一测试在改动前是 12fps。瓶颈在每帧几千次 `setTransform` + `drawImage`;真机有 GPU 时会好一些,但「三种形态都 60fps」这句原先的说法站不住
- **手部识别**:全部自己写,不引外部库、不联网、不留帧。摄像头帧降到 160 × 120,逐像素肤色判定(RGB 规则 + YCbCr 窗口)配一层会衰减的运动累积量,3 × 3 中值滤波,连通域标记后取「够大且真的在动」的那块,手型由径向分布的 r92 / r50 给出(拳头约 1.35,张开的手约 1.60)。整套跑在 30Hz,渲染仍是满帧
- **可访问性**:正文对比度 ≥ 4.5:1(light / dark 各自验证);`prefers-reduced-motion` 下 UI 过渡压平、hover 模式降级为直接切换;控件键盘可达,焦点环可见;触控目标 ≥ 44px
